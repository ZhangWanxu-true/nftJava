# NFTurbo 项目结构与启动运行方式

## 一、项目概览

**NFTurbo** 是一个数字藏品交易平台（Spring Cloud 微服务），技术栈：JDK 21、Spring Boot 3.2.2、Spring Cloud 2023、Dubbo 3.2、Nacos、RocketMQ、Seata、ShardingSphere 等。

---

## 二、项目结构（顶层）

```
项目根目录/
├── pom.xml                    # 根 POM，聚合 6 大模块
├── mvnw / .mvn/               # Maven Wrapper
├── nft-turbo-common/           # 公共能力（无 main，被其他模块依赖）
├── nft-turbo-auth/             # 认证服务（可运行）
├── nft-turbo-gateway/          # 网关（可运行）
├── nft-turbo-business/         # 业务聚合（内含多个可运行服务）
├── nft-turbo-admin/            # 管理后台（可运行）
├── nft-turbo-check/            # 对账/盘点任务（可运行）
└── nft-turbo-config/           # 配置与脚本（DDL、Nacos 配置、图片等，非 Maven 模块）
```

---

## 三、模块说明

### 1. nft-turbo-common（公共层，无 main）

提供各业务共用的能力，**不能单独运行**，只作为依赖被引用。

| 子模块 | 作用 |
|--------|------|
| nft-turbo-base | 基础配置（base.yml）、异常、分页、工具类等 |
| nft-turbo-config | Nacos 配置入口（config.yml） |
| nft-turbo-api | 对外 API 定义、DTO 等 |
| nft-turbo-cache | Redis 缓存配置（cache.yml） |
| nft-turbo-datasource | 数据源、分库分表（datasource.yml / datasource-sharding.yml） |
| nft-turbo-rpc | Dubbo RPC 配置（rpc.yml） |
| nft-turbo-seata | 分布式事务（seata.yml） |
| nft-turbo-mq | 消息（RocketMQ）封装 |
| nft-turbo-job | 定时任务（XXL-JOB） |
| nft-turbo-limiter | 限流（Sentinel） |
| nft-turbo-lock | 分布式锁 |
| nft-turbo-tcc | TCC 事务 |
| nft-turbo-es | Elasticsearch |
| nft-turbo-file | 文件/OSS |
| nft-turbo-sms | 短信 |
| nft-turbo-prometheus | 监控 |
| nft-turbo-skywalking | 链路追踪 |
| nft-turbo-web | Web 通用（统一返回、异常处理等） |
| nft-turbo-order-client | 订单客户端封装 |

### 2. nft-turbo-auth（认证服务）

- **入口类**：`NfTurboAuthApplication`
- **端口**：8082
- **职责**：登录、注册、Token 等认证相关。

### 3. nft-turbo-gateway（网关）

- **入口类**：`NfTurboGatewayApplication`
- **端口**：8081
- **职责**：统一入口、路由、鉴权、限流。

### 4. nft-turbo-business（业务域）

内部多个**可运行**服务 + 一个**聚合应用**：

| 应用/模块 | 入口类 | 端口 | 职责 |
|-----------|--------|------|------|
| **nft-turbo-app** | NfTurboBusinessApplication | 8085 | 聚合入口：依赖 chain/order/pay/user 等，对外提供交易等能力 |
| nft-turbo-user | NfTurboUserApplication | 8083 | 用户服务 |
| nft-turbo-trade | NfTurboTradeApplication | 8084 | 交易（下单、取消等） |
| nft-turbo-order | NfTurboOrderApplication | 9000 | 订单 |
| nft-turbo-pay | NfTurboPayApplication | 8088 | 支付 |
| nft-turbo-inventory | NfTurboInventoryApplication | 8087 | 库存 |
| nft-turbo-notice | NfTurboNoticeApplication | 8089 | 通知 |
| nft-turbo-chain | NfTurboChainApplication | 8090 | 上链 |
| nft-turbo-goods (interface) | NfTurboGoodsApplication | 8099 | 商品聚合（统一启动 collection+box 等） |
| nft-turbo-collection | （通过 goods 或 Dubbo 暴露） | 8086 | 藏品 |
| nft-turbo-box | （通过 goods 或 Dubbo 暴露） | 8091 | 盲盒 |

- **nft-turbo-app**：把 chain、order、pay、user、collection、box 等通过 Dubbo 聚在一起，提供完整业务流程，是“业务门面”。
- **nft-turbo-user / order / pay / trade 等**：独立微服务，可单独启动，通过 Nacos + Dubbo 互相发现与调用。

### 5. nft-turbo-admin（管理后台）

- **入口类**：`NfTurboAdminApplication`
- **端口**：9001
- **职责**：后台管理（藏品、盲盒、用户等）。

### 6. nft-turbo-check（对账/盘点）

- **入口类**：`NfTurboCheckApplication`
- **端口**：8092
- **职责**：库存对账、定时盘点任务等。

## 四、启动前准备

### 1. 环境

- **JDK 21**
- **Maven 3.6+**（或使用项目自带 `./mvnw`）

### 2. 中间件（按需启动）

统一配置在 **nft-turbo-common/nft-turbo-base/src/main/resources/base.yml**：

| 中间件 | 配置项示例 | 说明 |
|--------|------------|------|
| Nacos | nft.turbo.nacos.server.url | 必选，配置/注册中心 |
| MySQL | nft.turbo.mysql.* | 必选，业务库 |
| Redis | nft.turbo.redis.* | 必选，缓存/会话等 |
| RocketMQ | nft.turbo.rocketmq.url | 消息队列（业务流、订单等） |
| Dubbo | nft.turbo.dubbo.nacos.* | 使用 Nacos 做注册中心 |
| Seata | nft.turbo.seata.nacos.* | 分布式事务（不用可关 seata.enabled=false） |
| XXL-JOB | nft.turbo.xxl-job.* | 定时任务（可选） |
| Sentinel | nft.turbo.sentinel.* | 限流（可选） |
| Elasticsearch | nft.turbo.elasticsearch.* | 检索（可选，可关） |

首次启动前把 `base.yml` 里的地址、端口、密码改成自己环境（本机多为 `127.0.0.1`）。

### 3. 数据库

- 执行 **nft-turbo-config** 下的 DDL（如 `DDL_nfturbo.sql`、`DDL_seata.sql` 等）建库建表。
- 需要测试数据可执行 `DML_nfturbo_test_data.sql`。

## 五、启动方式

### 方式一：Maven 命令（推荐先整体构建）

在 **项目根目录**：

```bash
# 1. 整体编译安装（避免依赖找不到）
./mvnw install -DskipTests

# 2. 按需运行某一个应用（示例：业务聚合）
./mvnw -pl nft-turbo-business/nft-turbo-app spring-boot:run -DskipTests

# 其他示例：
# 网关
./mvnw -pl nft-turbo-gateway spring-boot:run -DskipTests
# 认证
./mvnw -pl nft-turbo-auth spring-boot:run -DskipTests
# 用户服务
./mvnw -pl nft-turbo-business/nft-turbo-user spring-boot:run -DskipTests
# 交易
./mvnw -pl nft-turbo-business/nft-turbo-trade spring-boot:run -DskipTests
# 订单
./mvnw -pl nft-turbo-business/nft-turbo-order spring-boot:run -DskipTests
# 支付
./mvnw -pl nft-turbo-business/nft-turbo-pay spring-boot:run -DskipTests
# 商品（含藏品/盲盒）
./mvnw -pl nft-turbo-business/nft-turbo-goods/nft-turbo-interface spring-boot:run -DskipTests
# 管理后台
./mvnw -pl nft-turbo-admin spring-boot:run -DskipTests
```

没有 `mvnw` 时可用本机 Maven：把 `./mvnw` 换成 `mvn`。

### 方式二：IDEA 运行

1. 用 IDEA 打开 **项目根目录**（打开根 `pom.xml`）。
2. 等待 Maven 导入完成；若依赖报红，对根项目执行一次 **Maven → Reload** 或 **Install**。
3. 找到对应入口类（如 `NfTurboBusinessApplication`、`NfTurboUserApplication` 等），右键 **Run** 或 **Debug**。

### 方式三：最小可跑组合（仅验证启动）

若只想验证“能起来”：

1. 启动 **Nacos**、**MySQL**、**Redis**（RocketMQ 可先不启，部分功能会报错但不影响部分接口）。
2. 修改 **base.yml** 中 Nacos、MySQL、Redis 为实际地址。
3. 先启动 **nft-turbo-user**（用户服务），再启动 **nft-turbo-app**（业务聚合）。  
   - 若未部署 Seata，需在 **nft-turbo-app** 的 `application.yml` 中保留 `seata.enabled: false`，避免 `service.vgroupMapping.default_tx_group` 报错。

## 七、依赖关系简述

- **nft-turbo-app** 依赖：chain、collection、box、goods-interface、inventory、notice、pay、order、tcc、user、seata、trade、prometheus、skywalking、limiter 等模块，通过 **Dubbo** 调用各微服务。
- 各业务服务（user、order、pay、trade、chain、collection、box 等）会依赖 **nft-turbo-common** 下的 base、config、rpc、cache、datasource 等，并从 **Nacos** 拉取部分配置（bootstrap 里 `config.yml` 指向 Nacos）。
- 请求链路可理解为：**网关(8081)** → **认证** → **业务（如 trade/app）** → 通过 **Dubbo** 调 user/order/pay/chain 等。

按上述结构理解后再按“启动前准备 + 启动方式”操作即可顺利运行和联调。
